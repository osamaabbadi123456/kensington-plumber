# Visual SERP and image brief

Status: research and creative direction only. Checked 2026-08-27. No image has been generated, sourced or added. This report complements `docs/IMAGE_PLAN.md` and `docs/IMAGE_PLAN_V2.md`; those plans remain the operational implementation reference.

## Observed visual patterns

- Inspected guide competitors use explanatory images, tables and FAQ modules more often than decorative photography. [Checkatrade’s tap guide](https://www.checkatrade.com/blog/expert-advice/tap-problems/) and [London Leak Specialist’s overflow guide](https://londonleakspecialist.co.uk/blog/overflow-pipe-dripping-outside-what-it-means) were direct observations.
- Retailer/specialist guides commonly use close-up fitting/product images. That treatment may be useful for recognition but can accidentally imply product endorsement, an installed item, or a completed repair.
- For symptom-led pages, an abstract diagram that points to an observable location is more truthful and useful than a stock “plumber at work” photograph.
- Image-pack / thumbnail availability on any individual query is **UNAVAILABLE** in this research environment; none is claimed.

## Implementation guardrails for a later visual batch

1. Record asset creator/source/licence, route, purpose, crop and status before use. Owner-supplied, commissioned or explicitly licensed material only.
2. Use explicit width/height or CSS aspect ratio and test 390px, 768px and desktop; never use a fixed crop that cuts the fault location.
3. Use `alt` only where the asset adds information not duplicated by adjacent text. Decorative local SVGs should be hidden from assistive technology.
4. Do not make a diagram the only safety instruction; text must remain complete if the image fails.
5. Re-run `npm run verify`, `npm run test:smoke`, and a route-specific visual check after adding any asset.
